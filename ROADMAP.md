# EduPortal Roadmap — 基智中學

A prioritised list of gaps found in the system review, for you to pick from.
Security fixes from the same review are already applied (see `SECURITY.md`).

Ranking is by **impact for a school** (teachers 60+, students, admin) vs effort.

---

## 🔴 Highest impact — build next

### 1. Agent document viewer + download  *(quick win)*
**Problem:** AI agents (Ada/Ethan/Andy/…) generate documents into `AgentDocument.content`, but **no page renders them**. Teachers approve/reject documents in `/teacher/admin/agents` without being able to see the body, and the generated work can never be opened or downloaded. `src/app/api/agents/doc/` is an empty directory.

**Build:**
- `src/app/api/agents/doc/[id]/route.ts` — GET a document, scoped to its owner or an admin.
- A viewer page (e.g. `/teacher/agents/tasks/[id]`) that renders `content` with the **existing** `src/components/teacher/AgentMarkdown.tsx` (already handles tables + Excel copy).
- A "下載 .md" button using a client Blob download (same pattern as the IT HEIC/PDF/QR tools).
- Show the document body inline in the approval card in `src/app/teacher/admin/agents/page.tsx` so approvers see what they sign off.

**Effort:** Small — the renderer already exists; this is wiring.

### 2. Teacher notifications
**Problem:** Pusher real-time is wired **only** in `src/app/student/page.tsx`. Teachers get nothing when an announcement is posted, a document is approved/rejected, or a behavior record is filed. For 60+ staff who don't watch the app, important events pass silently.

**Build:**
- Fire `pusherServer` (`src/lib/pusher.ts`) on announcement / doc-approval / behavior events (server helpers already exist).
- A notification center (bell icon + unread count in `TeacherSidebar`), backed by a `Notification` model.
- Optional: email (SMTP) digest for offline teachers.

**Effort:** Medium.

### 3. Audit-log viewer
**Problem:** `AgentAuditLog` records every agent action + approval, but there's **no UI** to read it — no accountability trail for a school.

**Build:** An admin list page reading `AgentAuditLog` with filters (user, action, date). Data already persisted.

**Effort:** Small.

## 🟡 Medium impact

### 4. Finish the stubbed committee tools
About **9 of 23** preset committee tools are label-only placeholders ("即將推出", no page). Fully built today: **IT only** (10 tools). Missing:

| Committee | Stub tools needing a real page |
|-----------|-------------------------------|
| ADMIN | 採購申請, 活動文件, 費用結算 |
| DISCIPLINE | 警告記錄, 欠交功課 |
| CURRICULUM | all 3 |
| ECA | 活動報名, 活動出席記錄, 比賽及獎項 |

Prioritise by which committees are actually active. Some overlap with the agent system (採購/通告 can be generated by Andy) — consider wiring those stubs to Keida instead of building standalone pages.

**Effort:** Medium–large (per tool).

### 5. Data export
Only `admin/users/export` (CSV) exists. No export for **behavior records, points, activities, attendance**. Schools need these for reports and parent communication. Add CSV/PDF export buttons (reuse the Excel-copy + Blob-download patterns already in the codebase).

### 6. Student experience parity
Students can see the dashboard, announcements, activities, missions, flashcards, and points — but have **no access to Keida/agents** and **cannot view their own behavior records**. Decide the intended scope: a read-only "my records" page for students would be high-value and low-risk.

## 🟢 Polish — do when convenient

- **PWA:** no `manifest.json` despite a mobile-first student UI and existing icons (`public/logo.png`, `keida-avatar.webp`). Add a manifest + service worker for install-to-home-screen.
- **Dark mode:** `globals.css` has no theme tokens / `prefers-color-scheme`. Add a dark palette.
- **Accessibility:** only ~7 `aria`/`role` usages in the whole app. Add form labels, focus states, and iconbutton `aria-label`s — important for assistive tech and older staff.
- **Global search:** none today. A command-palette style search across announcements / students / tools.
- **Help / onboarding:** no help page or first-run tour — significant friction for non-technical teachers.
- **Empty/error states:** some fetches swallow errors silently (e.g. `student/page.tsx` if `/api/classes` fails) — add visible error UI.
- **Correctness bug:** `src/app/api/students/[id]/portfolio/route.ts` uses `studentName: { contains: studentId }` which matches the wrong records — should filter by the student id/relation.
- **Soft-delete:** schema has no `deletedAt`; deletes are permanent. Consider soft-delete for users/announcements/records so accidental deletions are recoverable.

# 班級電子黑板

## 入口與設定
- 班級入口：`/blackboard/login`；班別及共用密碼登入後只可查看本班黑板。
- 教師入口：課堂頁面的「班級黑板」，或 `/teacher/classes/<classId>/blackboard`。
- 班主任、班級擁有人或管理員先在「時間表與登入」設定至少 8 字元的班級密碼並啟用。未設定時不能登入；管理員可使用下述批量預設。
- 每次儲存登入設定會撤銷舊裝置會話；裝置會話最多 8 小時。停用後下一次讀取立即拒絕。
- 密碼只以 bcrypt 雜湊儲存，請透過學校選定渠道告知班級；不要在 GitHub 記錄密碼或學生資料。

## 教師權限及使用
班主任／擁有人／管理員管理共用版面、課表、密碼及本班卡片。任教老師依已匯入時間表取得班別及科目，只可發布自己的科目內容並修改自己的便條。多班／全校便條只有管理員可建立及修改；「選取全部」只包含當時已建立的班別。

在「公告與便條」新增便條、公告、活動或留堂安排。既有教師內部公告、活動及紀律紀錄不會自動公開；教師明確挑選適合全班閱讀的文字再發布。留堂顯示班別、學號、日期、開始／結束時間及地點；不顯示姓名。可設定顏色、置頂、顯示起訖及詳情連結。全部時間為香港時間。

在「黑板排版」拖動把手、用方向鍵或按鈕移動／調整大小，然後儲存共用版面。手機以儲存次序單欄排列，「提前」可調整手機次序。多人同時儲存時舊版本會收到 409；保留草稿、重新讀取資料、檢閱新版本後再選擇套用草稿或放棄。

## 資料及時間表
功課取本班最近 100 份；未解決欠交／缺席未交取最近 1000 筆，分開顯示；補交後需教師在原有功課紀錄更新狀態。學號取本班名冊；未設定學號時直接提示，不以姓名代替。

時間表採星期一至五，可選「使用已匯入時間表」或班主任手動課表。自動模式採原系統的有效學期，僅明確匹配班別；合班使用明確分隔的代碼，例如 `1A/1B`。不推測含糊代碼。手動模式替代該班自動課表。

管理員設定全校課節開始／結束時間及小息／午膳。參考時間須先核對及儲存才會用於「目前／下一節」。具名時段名稱須與課表完全一致。未設定資料時顯示提示，週末不標示上課中。這一版按每週課表顯示，不提供假期／臨時調課覆寫。

班級畫面每 30 秒更新；分頁隱藏時暫停，返回時立即更新。連線失敗保留上一份內容並標示最後更新時間，不把錯誤顯示為沒有欠交。會話失效時清空畫面並回班級登入。

## 本地驗證
使用拋棄式、本地 PostgreSQL，從現有 schema 建立基線後只套用新黑板 SQL。測試不使用原有 demo seed，不可連正式資料庫。

```sh
npm ci
npm run test:blackboard
npx tsc --noEmit
npm run lint
npm run build
# 以下兩項須先啟動同一個本地資料庫及 Next.js app（預設 3100）
node --import tsx tests/blackboard-http.ts
node tests/blackboard-browser.mjs
```

HTTP 及瀏覽器測試須設定本地 `DATABASE_URL`、`DATABASE_URL_UNPOOLED`、`AUTH_URL`、`AUTH_SECRET`；測試會建立固定 id 的合成帳戶及班別，請每次用新資料庫。瀏覽器測試另需 Playwright + Chromium，可由 `BLACKBOARD_PLAYWRIGHT_MODULE`、`BLACKBOARD_CHROMIUM_MODULE`、`BLACKBOARD_CHROME_EXECUTABLE` 指定本機安裝，不屬於產品依賴。請勿把合成測試帳戶當成正式帳戶。

## 正式發布及回復
這個專案原本沒有 Prisma migrations 基線。新增的 `prisma/migrations/202610230001_class_blackboard/migration.sql` 是相對於原 schema 的新增表及外鍵 SQL，**不能未經 baseline 就對現有資料庫執行 `prisma migrate deploy`**。

正式發布前另行確認：備份並驗證還原、在相同 PostgreSQL 版本測試 SQL、於維護窗口套用 reviewed SQL、部署 Prisma client 及程式、設定班級帳戶、執行校方驗收。不能以本地 build 或 PGlite 測試代替正式 PostgreSQL 驗收。不要使用現有無 `:local` 後綴的資料庫腳本作開發。

回復時先停用班級黑板，還原前一版程式，保留新增資料表；不要為 rollback 刪表。封存及過期卡片保留於教師管理頁面。學年資料清理及過期會話清理須由管理員依學校保留政策處理，此版沒有自動刪除或新增排程服務。

## 登入節流與代理設定
登入每班每 15 分鐘最多 10 次嘗試，來源最多 30 次；未配置可信來源 header 時採全站共用每 15 分鐘 300 次上限。`BLACKBOARD_TRUSTED_IP_HEADER` 只可指向反向代理會覆寫且不允許外部自填的單一來源位址 header，否則保持未設定。黑板登入節流失去資料庫連線時拒絕登入；不沿用既有 fail-open 教師登入節流。

## 年級選修及小組課表

自動課表除了本班明確課堂，也列出同年級S4-X1、S3-G1這類分組記錄，保留該節每個實際科目，不以一個科目覆蓋其他科目。X1顯示「選修一」；S3-G1顯示「中文／英文／數學分組」，接受S3- G1等空格。不同年級不混入，教師重複記錄合併，但不同分組不合併。

沒有個別學生分組名冊，因此清楚標為「年級分組參考」，不表示全班須出席每個科目；請按實際選科／分組出席。本次不改教師權限的班別配對規則。手動課表保留教師輸入，從自動切為手動時會保留分組標記。無資料庫變更。

## 批量設定班級預設密碼

管理員到系統設定 /teacher/admin/settings →「批量設定班級黑板密碼」→「預覽所有班級」，核對名單後勾選確認並按「套用所有班級預設密碼」。標準班別1A至6Z的規則為keichi加小寫班別，例如1A為keichi1a、5A為keichi5a。套用會覆蓋現有黑板密碼、啟用列出的黑板並登出舊班級裝置；不影響個人帳戶。非標準班名／S4-X1等分組記錄略過；重複的登入班名會阻止整批執行。

密碼以獨立bcrypt雜湊儲存；API不回傳明文。只限仍有ADMIN角色的管理員，要求同源、明確確認及最新預覽hash。整批在交易中執行，設定版本／會話版本增加。日後可個別修改密碼；不會每次部署自動覆寫。新建班級需再次執行預設或個別設定。沒有新增資料表，不需db:push來套用此功能，但原有Blackboard資料表必須已建立。

程式部署不等於已重設正式班級密碼；必須由管理員實際按下「套用」並見成功班數，才表示正式資料已更新。

批量密碼驗證：27項黑板單元測試、TypeScript、lint、production build通過；本地合成資料庫／HTTP驗證5A新密碼登入、舊密碼與舊會話失效、管理員權限、同源及過期預覽拒絕。課後班整合測試亦通過。未操作正式資料庫，未完成瀏覽器視覺驗收。

## 按日期查看課表及活動

班級黑板頂部提供前一天、日期選擇、後一天及今日；預設香港今日。每日課表第1至10節各一格，同節科目及分組合併顯示，沒有資料的節次標示未設定。保留全週檢視及其他具名安排。課表屬每週恆常時間表，假期／調課仍以學校公告為準，其他日期不顯示即時上課狀態。

當日活動區只顯示已批准、該班學生已獲分配且與所選香港日期重疊的公開活動，課後班沿用已整理的Activity及參加名單；未完成整理的課後班不會臆造顯示。只回傳本班學號、標題、時間及地點，無姓名／學生ID／備註；學生支援私人活動沿用保密規則隱藏。與卡片發布時段分開處理，日期切換不會提早公開未發布便條。

活動總覽新增活動時，以目前資料庫角色及所選組別主席權限決定自動批准：ADMIN或該組別主席即時批准、記錄批准者及時間，並沿用現有行事曆發布；其他教師待批核。未選組別時僅ADMIN自動批准。不追溯修改已有待批活動。

本次無schema變更。29項黑板及12項課後班單元測試、TypeScript、lint（原有警告）、production build及合成資料庫HTTP整合測試通過。包含跨日邊界、班級名單隔離、私人活動／待批活動排除、課後班分類及自動批准權限。獨立審查沒有重大問題；已知輕微問題為切換日期後可能在下一次畫面更新前短暫顯示前一日的連線錯誤提示（不會顯示前一日活動資料）。未完成瀏覽器視覺驗收及正式部署驗收。
